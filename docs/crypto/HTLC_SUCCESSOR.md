# Complete native HTLC successor candidate

The additive `transaction_circuit::smallwood_htlc` module implements a complete one-input/one-output native-asset relation. It does not extend the unchanged RP05 program or authorize its production route. Its separately identified relation is `hegemon.native.htlc.HGV9HT01.v1`.

A Lock action proves ordinary SingleKey input authorization, depth-32 V8 note inclusion, native nullifier derivation, positive values and conservation including the exact public fee. It creates a V8 note whose complete seven-word owner commits a shared five-word nullifier key and a private policy. The policy commits full network ID, standard SHA-256 digest, complete seven-word claim/refund authorities, their four-word encryption recipients, timeout and secret-release mode. Claims prove the private preimage and claim credential; refunds prove the refund credential and authenticated parent height at least the deadline. Both pay the exact recipient committed in that branch's policy and consume the same branch-independent native nullifier.

Claims remain valid after timeout. Canonical first spend wins through ordinary note/nullifier consumption; a local timer is not authority. Admission must validate the exact manifest network ID, parent hash/height and Merkle root, then repeat checks during ordered state application. Heights are 48-bit and values 56-bit, making the range-checked maturity and balance equations free of prime-field integer wrapping.

The prover specializes the public branch: Lock and Refund omit SHA and use canonical zero secret bits. A refund requires no hashlock preimage. Hidden-on-Hegemon policies transport no secret; public-on-Hegemon policies bind and expose exactly the claim preimage. HGN/BTC initially uses Hegemon as the longer-timeout leg, receiving the secret from Bitcoin. End-to-end Bitcoin orchestration remains separately qualified.

The public `HtlcStatement` binds network, exact parent, state root, nullifier, output commitment, ciphertext hash, fee, branch and secret-release bytes before challenge sampling. The native route must also bind the ciphertext bytes to that hash with the existing canonical framed digest. The proof does not establish that arbitrary encrypted bytes were constructed honestly; this is the same recipient-recovery responsibility as the existing V8 construction. Private `HtlcWitness` and `HtlcPolicy` have no Debug or serde implementation.

## Actual development qualification

On 2026-10-04, the entire combined Claim relation produced a 1,243,002-byte strict-SMZ1 development proof. Proving took 30.073 seconds with two threads; verification took 0.687 seconds. A separate process reading only public statement and proof accepted in 0.712 seconds. An unchecked complete changed-secret arithmetic/SHA trace generated a proof in 29.023 seconds and the actual verifier rejected it. Changed network, parent, payout commitment and trailing proof byte also rejected. The honest-plus-negative command peaked at 2,001,027,072 bytes RSS.

Public evidence is retained outside the repository at `/private/tmp/premainnet-htlc-fullproof-20261004-r2`; it contains no private witness or secret. Its exact profile is development-only SMZ1/K64/degree2/rho5/open5/beta2/N2^20/q23/eta5/PoW0/disjoint-coset/SHA-512. This is not the RP05 SMZA profile, a transferred formal/security receipt or production authorization. RP05's 164,113-byte ceiling remains unchanged.

That receipt applies only to the exact historical source recorded in it. The subsequent SMZB/SMZC engine merge, strict profile and immutable identity split change the HTLC relation digest; qualification of the final merged source requires fresh proofs.

Full scalar Lock/Claim/Refund tests passed 4/4 in 0.77 seconds before CSR canonicalization; the actual engine then exposed duplicate variable terms, corrected by merging coefficients and sorting each equation. The successful real proof uses the repaired canonical CSR. A focused verifier-argument-order defect was found and repaired before actual proof qualification. Negative tests exercise all seven claim authority limbs, both credential/nullifier key tails, payout recipient/owner, amount, fee, position, network, digest/preimage, maturity and release mode.

The source is intentionally factored into degree-two multiplication equations with constrained intermediate wires; this includes Poseidon x^7 and SHA parity/majority. It does not claim a degree-seven function has become degree two without intermediate constraints. The Claim graph has 486,276 canonical wires, 19,731 packed rows, 4,044 multiplication batches and 1,003,794 linear equations; Lock/Refund use approximately 4,103 rows.

## Required launch qualification

A dedicated SMZC successor wire/profile and exact public-statement inclusion in strict Merkle leaves are implemented. They require fresh exact-source artifacts, full relation/security review and any necessary formal acceptance evidence, route-specific byte bounds and unchanged self-contained carriers through wallet/RPC, relay, mempool, mining, block import, sync, restart, reorg and fresh nodes. The full successor remains failclosed until those production-authority obligations are complete. Neither this document nor the development proof opens a production route.

The dedicated SMZC source binds a fixed 576-byte full statement directly into every strict leaf with unique transcript and leaf domains. Independent review rejected automatic reuse of the initial unpublished q38 profile: the combined relation's DECS polynomial degree is far above RP05's degree 405 and uses a different agreement threshold. A fixed-response polynomial screen does not transfer that accepted-execution QROM endpoint.

The unpublished SMZC profile now uses 58 DECS queries and its own 80-candidate fixed sampler/domain, retaining N2^23/rho5/open6/beta2/eta5. Historical sampler sequences and RP05 bytes remain unchanged. A conservative generalized degree-aware numerical ledger estimates 134.28 bits at the stated lifetime bound; this is a numerical assurance boundary, not a transferred RP05 theorem or production approval. The literal serializer hint and actual full proofs must be checked on the final merged source.

The isolated `full_htlc_artifact --project` example reports the exact source-owned serializer hint and 576-byte public binding for each branch. `full_htlc_candidate_artifact --generate (lock|claim|refund) fresh-public-directory [--invalid-witness]` retains only the public statement, SMZC proof and sanitized measurement receipt. It checks changed public components, exact trailing-byte rejection and actual size against the hint. Its optional invalid-witness mode evaluates a complete changed-preimage or changed-credential trace without the host equation audit and requires real verifier rejection. A separate `--verify public-directory` process loads only those public files. These deterministic fixtures qualify the relation/profile; they do not qualify chain transport, Bitcoin orchestration or release authority.
