## Verdict

The current tree does not establish either endpoint required by this contract:

1. adaptive, repeated, witness-free zero knowledge against a quantum adversary
   with coherent access to the actual shared SHA-512 oracle; or
2. extractive knowledge soundness for accepted production proof bytes with
   respect to the fixed repaired transaction semantics and exact relation ID.

The checked arithmetic, algebraic hiding maps, compressed-oracle machinery,
wire parsers, replay fixtures, and deterministic candidate inverse are useful
prerequisites. None is an endpoint theorem. Production is correctly fail
closed: `smallwood_poseidon2_production_capability()` returns `None`, and the
authority path denies the V8 binding while that capability is absent
([source](../../../protocol/versioning/src/lib.rs#L502-L554)).

This contract is satisfied only by proofs whose games are generated by the
actual algorithms and whose implementation refinements reach the active native
acceptance path. A record populated with desired probabilities, an empty
proposition, a retained fixture, or a caller assertion is not evidence.

## Required endpoints

### Quantum witness-free privacy

Define executable experiments, not fields containing claimed probabilities.
In pseudocode, the required interface is:

```text
RealZK(A, Qmax, Tmax):
  sample the real prover randomness source
  initialize one shared raw SHA-512 oracle H
  let A interact coherently with H before, between, and after proof requests
  for each adaptive request (public_context, statement, witness, auxiliary_input):
    require ExactV8RelationSemanticValid(statement, witness)
    run the actual SMZ9 prover with witness, context, coins, and H
    return the exact externally visible result
  return A's final classical output and residual quantum state

SimZK(A, Sim, Qmax, Tmax):
  initialize the simulator's one shared raw SHA-512 oracle interface
  give A the same coherent, adaptively interleaved interface
  for each adaptive request (public_context, statement, witness, auxiliary_input):
    require ExactV8RelationSemanticValid(statement, witness)
    discard witness at the simulator boundary
    run Sim(public_context, statement) without a witness
    return the exact externally visible result
  return A's final classical output and residual quantum state
```

`Sim` MUST NOT receive, query, reconstruct, or be parameterized by the witness.
Its oracle programming is internal; the adversary observes the resulting
coherent oracle behavior, not a program table. The real and simulated games
MUST share the same request grammar, abort behavior, output lengths, public
context, and lifetime oracle.

For every allowed physical quantum adversary `A`, the theorem MUST derive

```text
Adv_zk(A; Q, T) =
  distance(FinalCQState(RealZK(A)), FinalCQState(SimZK(A)))
  <= eps_zk(Q, T)
  <= 2^-128.
```

Trace distance of final classical-quantum states, or an equivalent universal
distinguisher theorem, is acceptable. Equality of selected classical
marginals is not. The theorem must quantify over adaptive repeated requests,
not prove a single fixed statement/witness fixture and then multiply an
unrelated number by `T`.

The current `Smz9WholeViewExperiment` instead accepts real and simulated
probability functions as caller inputs
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9ZeroKnowledge.lean#L1828-L1880)).
Its conditional reduction therefore does not define this endpoint. The source
also explicitly leaves the SHA-512 QROM instantiation and repeated whole-view
hybrid uninhabited
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9ZeroKnowledge.lean#L1983-L2065)).

### Extractive quantum knowledge soundness

The required quantifier order is constructive:

```text
for every allowed physical quantum proof adversary A,
there is an efficient extractor Ext(A), defined by the reduction,
such that the joint extraction experiment produces
  (public_context, exact_proof_bytes, verifier_result, extracted_witness?)
and
Pr[
  VerifyProductionBytes(public_context, exact_proof_bytes) = accept
  and (
    extracted_witness? = none
    or not ExactV8RelationSemanticValid(decoded_statement,
                                        extracted_witness)
  )
] <= eps_ks(Q, V) <= 2^-128.
```

`V` is the separately bounded number of adversarial verification or extraction
targets. It MUST NOT be silently identified with `T`, which counts honest proof
views below. If a reduction states a per-target bound, a proved union or joint
experiment must account for `V`.

`VerifyProductionBytes` denotes the exact cryptographic candidate-verifier
predicate that the release would authorize, including canonical decode,
profile, statement, binding, and transcript checks. It does not denote the
current outer proof-authority decision, which always denies this binding while
the capability is `None`; using that denial as the verifier would make the
security theorem vacuous.

The extractor may use measurement, rewinding, recording, or compressed-oracle
state only as permitted by its stated quantum model. It MUST expose its
success event and resource overhead. A witness existential supplied as a
premise, a post-hoc classical inverse of caller-supplied oracle data, or the
claim that no witness exists is not a knowledge extractor.

The extracted object must cross both boundaries:

```text
accepted proof bytes
  -> one committed codeword / polynomial object
  -> one packed HGV8RP03 witness accepted by the pinned program
  -> one decoded witness satisfying ExactV8RelationSemanticValid.
```

The deterministic candidate inverse currently reaches exact packed-program
satisfaction only after it is given a suitable full committed oracle
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9OracleExtraction.lean#L11-L28),
[source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9ConcreteOracleExtraction.lean#L6-L12)).
It does not prove that one accepted twenty-opening proof supplies that oracle.

### Full-action and no-counterfeit corollary

Knowledge of the private relation is necessary but not sufficient for a
consensus no-counterfeit statement. A production corollary MUST additionally
prove that the accepted native bytes bind:

1. the independently supplied consensus context;
2. every inline or sidecar ciphertext byte string and its commitment;
3. the exact state transition, nullifier, commitment, stablecoin, and supply
   semantics; and
4. the canonical block/reorg/restart state to which those semantics apply.

The target is `ExactV8FullActionSemanticValid`, followed by the already
specified ledger transition theorem. The formal semantic layer deliberately
keeps consensus-context and ciphertext binding outside the private relation
([source](../../../formal/lean/Hegemon/Transaction/Poseidon2V8SemanticAdequacy.lean#L192-L217)).
The current supply-chain theorem consumes caller-supplied extraction and
semantic evidence and labels itself conditional rather than deployed
([source](../../../formal/crypto/HegemonCrypto/SmallWoodProductionSupplyChain.lean#L214-L289)).

## Physical quantum model

The final privacy and knowledge games MUST use one of these equivalent
well-formed models:

1. finite-dimensional pure states with complex-linear unitary/isometric
   operations, explicit ancillas, and measurements represented by a complete
   quantum instrument; or
2. density operators with completely positive trace-preserving channels, with
   trace-nonincreasing branches used only as members of a complete instrument.

A subnormalized complex-linear contraction may represent a selected
measurement branch. Any conditioning on that branch MUST charge its success
probability. Uncharged postselection is forbidden.

`FiniteQrom.NormPreservingStep` is not by itself a physical-operation
certificate: its `apply` field is an arbitrary `State -> State` function and
its only law is pointwise norm preservation
([source](../../../formal/crypto/HegemonCrypto/FiniteQrom.lean#L123-L160)).
That interface permits nonlinear and anti-linear maps. It MUST NOT be the final
adversary semantics unless complex linearity and the appropriate channel laws
are added.

This observation does not invalidate the active CMS operator lemmas. The CMS
path lifts an explicit finite complex matrix on adversary registers and derives
additivity and database blindness
([source](../../../formal/crypto/HegemonCrypto/CmsOracleSimulation.lean#L876-L964));
the compressed query is isometric on its reachable strict support
([source](../../../formal/crypto/HegemonCrypto/CmsCompressedOracleUnitary.lean#L924-L964)).
Those lemmas remain usable after the final game instantiates physical
operations and valid measurement branches.

## Complete adversary observation

The privacy game MUST preserve the joint distribution of everything the real
system exposes, in order:

- exact public statement, binding, network, relation, and consensus-context
  bytes;
- exact proof bytes, including length, canonical encoding, and repeated bytes;
- every externally observable prover/verifier result, abort, rejection, and
  ordering effect included in the claimed API surface;
- all earlier, rejected, orphaned, side-fork, wallet-generated, and repeated
  proof views in scope;
- coherent pre-, inter-, and post-proof queries to one shared raw SHA-512
  oracle, including correlations with programmed points; and
- the adversary's final residual quantum register together with its classical
  output and transcript.

Internal simulator coins, hidden program tables, and audit diagnostics are not
automatically visible. If implementation behavior leaks any of them, that
leakage becomes part of the real observation and must be simulated.

The current internal observation record usefully retains raw keys, programs,
prior queries, ordered query traces, verifier traces, and coin ledgers
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9WholeViewObservation.lean#L137-L295)).
Its static projection intentionally drops the oracle interaction and is
explicitly not a ROM/QROM adversary view
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9WholeViewObservation.lean#L297-L325)).
Neither structure alone is the required final cq-state experiment.

## Resource contract

The security statement MUST bind resources before evaluating any numeric
margin.

### `Q`: global adversarial quantum queries

`Q` is one protocol-lifetime upper bound on coherent adversarial queries to the
shared, exactly framed SHA-512 oracle. It is not per proof, per block, per
epoch, per process, per node, or per restart. The current arithmetic evaluates
an analysis point `Q = 2^64`
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9QromAccounting.lean#L37-L53)).
Production acceptance requires an independently justified policy/model binding
the claimed adversary class to that limit.

### `T`: observed or generated honest proof views

`T` counts every honest proof view generated or exposed within the lifetime
experiment, including wallet-generated, rejected, orphaned, side-fork, and
repeated-verifier views. It is not the number of canonical accepted actions.
The source states this distinction directly
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9AdaptiveFiniteAccounting.lean#L113-L143)).

The current eager exposure arithmetic uses

```text
H_program(T) = 2^24 * T
E_program(Q,T) = Q + H_program(T).
```

This is a programming-event envelope, not automatically the exact number of
raw SHA-512 calls made by honest prover, simulator, rejection samplers, nonce
trials, and reduction code. The final theorem MUST derive a source-complete
`H_sha(T)` or prove that `H_program(T)` dominates every relevant raw exposure.
It must then use one consistent `E = Q + H_sha(T)` wherever the reduction
requires total oracle exposure. Existing accounting definitions expose the
current SHA and Poseidon2 counts
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9QromAccounting.lean#L341-L365)).

### Other resources

`T` is not quantum running time or a T-gate count. The accepted theorem MUST
also state the adversary's computational model and time/circuit bound, the
extractor's overhead, memory if relevant, and `V` for adversarial proof targets.
Any primitive theorem whose advantage depends on time, gates, queries, data,
or multi-target count must consume the matching bound. No symbol may be reused
with a different meaning between privacy, soundness, and primitive analyses.

fixed before an independent uniform `5 x 140` matrix; it explicitly excludes
the SHA challenge and twenty-opening transfer
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9DecsDegreeEnforcement.lean#L6-L17)).

two-candidate obstruction already exceeds the fixed-oracle bound, while the

([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9AccumulatedExtraction.lean#L5-L20),

uniform twenty-subset, a word differing at one fixed cell is missed with exact
probability `1 - 20/2^23`. K2 therefore needs a proximity/list-decoding theorem,
a valid multi-transcript extractor, or another explicit bridge. The exact
degree-387/twenty-root theorem is a bound for a fixed nonzero polynomial and
states that executable challenge derivation is outside its result
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9AdmissibleRootProbability.lean#L168-L248)).

The logical-oracle file correctly records the three missing source bridges as
uninhabited propositions: exact round transition, exact failure selector, and

([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9LogicalOracle.lean#L941-L1026)).
They are blockers to discharge, not tokens to bypass.

## Primitive and assumption ledger

The final theorem and release dossier MUST classify each item below. Algebraic
theorems, computational assumptions, implementation refinements, measurements,
and release authority are separate evidence classes.

| Primitive or source | Required statement | Classification |
| --- | --- | --- |
| SHA-512 transcript oracle | Exact framed/counter-mode Rust calls are represented by one shared quantum random oracle, including adaptive programming, rejected trials, collision/preimage events, and all honest/simulator/reduction exposures. | Computational model plus concrete reduction/assumption. Digest width alone is no evidence. |
| SHA-512 Merkle commitment | Accepted paths bind one tree/word except under a quantified quantum collision/binding event. Duplicate raw keys and cross-role framing are handled. | Computational assumption/reduction tied to exact grammar. |
| Poseidon2 width 16 | Exact Rust rows refine the pinned Lean permutation and all 125 live plus 3 padding evaluations are counted. Collision/preimage or sponge-indifferentiability security for the seven-limb output is justified against the stated quantum adversary. | Implementation refinement plus external cryptanalysis/assumption. Generic `q^3/p^7` and `q^2/p^7` arithmetic does not prove the permutation is ideal. |
| BLAKE2b-384 ciphertext commitment | Exact RFC 7693 unkeyed 48-byte implementation, framing, six-word projection, and the binding property needed for admitted ciphertext bytes. | Implementation refinement plus external collision/binding assumption. Lean currently leaves the primitive opaque ([source](../../../formal/lean/Hegemon/Transaction/Poseidon2V8SemanticSpecification.lean#L729-L815)). |
| Goldilocks field and polynomial lemmas | Exact finite-field arithmetic, root bounds, injective coset points, interpolation, and matrix counting. | Mathematical theorem; no cryptographic assumption. |
| Runtime entropy | Successful system and injected RNG calls are fresh, independent, uniform, nonrepeating as required across concurrency; failure/abort behavior is modeled. | Operational/implementation assumption with platform evidence. |
| Compiler and parsers | Rust source, built machine code, Lean interpreter, statement lowerer, and canonical byte decoders are universally equivalent on arbitrary inputs. | Implementation refinement, not a primitive assumption. |
| Lifetime resources | `Q,T,V,time,H_sha` bound the deployed threat model for the capability lifetime. | Governance/operational assumption backed by an explicit model, not inferred from block caps. |
| Review and activation | Authenticated independent review and a finite-lifetime release decision cover the exact artifact hashes. | Release authority, not cryptographic evidence. |

No classical discrete-log, factoring, or other Shor-vulnerable assumption may be
counted toward the post-quantum margin. Any new assumption must state its exact
security game and quantum resource dependence.

## Quantitative acceptance

Before claiming bits, the proof MUST provide event decompositions whose union,
hybrid, or reduction inequalities are themselves proved. At minimum:

```text
eps_zk(Q,T) =
    eps_rng
  + eps_honest_joint_law
  + eps_oracle_programming(Q,T,H_sha)
  + eps_sampler_abort(T)
  + eps_sha512_qrom(Q,T,H_sha,time)
  + eps_repeated_view(Q,T)
  + eps_privacy_refinement

eps_ks(Q,V) =
    eps_acceptance_event_refinement
  + eps_sha512_raw_to_logical(Q,time)
  + eps_merkle_binding(Q,time)
  + eps_proximity_or_list_decoding(Q,V)
  + eps_decs_degree_and_selection(Q,V)
  + eps_piop_roots_and_sampler(Q,V)
  + eps_cms_instability_and_measurement(Q,V)
  + eps_extraction_and_semantic_refinement
  + eps_poseidon2_and_other_primitive_binding(Q,V,time).
```

The displayed sums are required categories, not permission to invent terms.
Each term MUST cite the exact event theorem and use consistent resources. Terms
may be removed only by an exact refinement/equality theorem; they may be
combined only by a proved tighter composition.

Both endpoint totals MUST be at most `2^-128` independently at the approved
maximum resources. A no-counterfeit bound must then add only the genuinely
additional external-binding and ledger events. Any claim combining privacy,
knowledge soundness, and no-counterfeit failure into one event MUST also prove
that combined event's total is at most its advertised target. The existing
`exactComposedRatio` is useful accounting scaffolding, but its own source says
that transition, selector, CMS, SHA, whole-view, lifetime-budget, event, and
review premises are not constructed there
([source](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9AdaptiveFiniteAccounting.lean#L1542-L1667)).

The companion quantum-reduction assessment records why a generic four-stage
measure-and-reprogram route is quantitatively unusable at `Q = 2^64` and why
the selected CMS and adaptive-programming routes still need protocol-specific
event bridges ([assessment](quantum-reduction.md)). A theorem with a loss larger
than the target is a no-go even if every qualitative premise is eventually
proved.

## False-completion blockers

Any one of the following makes a completion claim invalid:

1. The simulator receives the witness, witness-derived secret state, or a
   caller-supplied honest/simulated probability.
2. Privacy is proved only for proof bytes, selected marginals, affine ranks,
   finite-fiber entropy, or a classical transcript while omitting the shared
   coherent oracle and residual adversary state.
3. A single-proof statement is multiplied by `T` without a sequential adaptive
   composition theorem, or the oracle/resources reset per proof, block, epoch,
   process, restart, or node.
4. `T` is replaced by accepted on-chain actions, or `Q` is treated as a
   per-proof budget. A block cap is not a lifetime view cap.
5. Programming input entropy is asserted without proving the required joint
   input/output law and independence conditions. Marginal uniformity is not an
   adaptive-reprogramming theorem.
6. An arbitrary norm-preserving state function is treated as a physical
   quantum operation, or postselection is normalized without charging its
   probability.
7. The fixed-oracle `p^-5` matrix result is applied after selecting a residual
   from the observed matrix without a family/selection loss.
8. Twenty accepted openings are treated as full `2^23`-domain agreement without
   proximity, list decoding, or a valid extraction theorem.
9. Uniform finite-field challenge lemmas are applied directly to SHA-derived
   bounded nonce/rejection samplers without an exact raw-oracle reduction.
10. The logical oracle is assigned the cardinality of a product of independent
    outputs when the concrete SHA-512 call returns one 512-bit digest.
11. An extracted polynomial/oracle is called a knowledge witness before packed
    program acceptance and fixed semantic adequacy are proved.
12. A caller-selected `semanticTarget` substitutes for
    `ExactV8RelationSemanticValid`, or external context/ciphertext checks are
    hidden inside an unproved relation receipt.
13. Proof-byte canonicality, an accepting fixture, mutation tests, KATs,
    retained artifacts, or passing build/formal gates are presented as
    universal verifier, compiler, or semantic refinement.
14. SHA-512's 512-bit output, Poseidon2's seven field limbs, or BLAKE2b-384's
    name is presented as a post-quantum security proof without the exact game
    and quantum bound.
15. Empty inductive propositions, unavailable receipt structures, axioms,
    `sorry`, opaque desired equalities, or caller booleans are used to inhabit a
    security premise.
16. A conditional-supply theorem, arithmetic ledger, local proof artifact, or
    independent test result is treated as production authority.
17. The currently disabled outer authority decision is used as an always-reject
    verifier to obtain a vacuous soundness theorem for the candidate backend.
18. Proofs are transported through sidecars, receipts, caches, aggregates, or
    regenerated forms instead of preserving the exact self-contained bytes
    through every production lifecycle path.
19. A release flips the capability before independent review, exact artifact
    authentication, complete lifecycle verification, and an explicit finite
    lifetime/resource policy.

## Activation rule

Keep the production capability disabled until P7, K8, and R0-R4 are all
complete for the fixed subject above, both endpoint losses independently meet
the `2^-128` target at approved resources, and the release authority explicitly
creates a finite-lifetime capability bound to authenticated source, theorem,
binary, vector, and review artifacts.

Changing a parameter, transcript frame, compiler, verifier path, semantic
predicate, RNG path, resource policy, or proof carrier invalidates the affected
descendants in the dependency graph and requires them to be rerun. No local
artifact or prior profile inherits authority automatically.
