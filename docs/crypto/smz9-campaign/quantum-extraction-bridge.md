# SMZ9: the quantum-to-source extraction boundary

Date: 2026-09-07. Scope: source inspection and primary-literature assessment;
no Lean implementation, build, or production authorization. The source tree was
changing concurrently. In particular, `SmallWoodV8Smz9McaSourceBinding.lean`
explicitly identifies itself as uncredited and paused at the disk reserve.

## Verdict and decisive next theorem

**The supplied-table decoder is not yet an extractor for accepted SMZ9 bytes.**
There is an efficient finite procedure for decoding a supplied table, and
established quantum techniques for extracting Merkle commitments. Their
composition with this exact Fiat–Shamir transcript remains unproved.

The immediate quantum theorem to build is **coherent SMZ9 Merkle-prefix
substitution**, not another accepted-bytes record with an extraction field.
It must replace the root in an adversary's *superposed transcript query* by a
canonically extracted, partially recorded source while preserving the physical
oracle game up to a derived error. It must cover the source-owned leaf/node
grammar and every shared raw-oracle call. Classical extraction when a prover
announces a root does not provide this operation for a noninteractive prover.

This is not a claim that a new general cryptographic framework is necessary.
Chiesa–Di–Hu–Zheng's 2026 framework specifically addresses coherent commitment
extraction; the concrete SMZ9 instantiation and numerical constants are the
missing work. Independently, the actual response decoder still needs its
round-by-round failure bound. Neither missing theorem can be discharged by
putting the desired success probability into a structure.

## Concrete extraction procedure and its chronology

Let `D` be a classical basis value of a compressed raw-oracle database, `r` a
root, `A` the DECS matrix, and `R` the five degree-387 responses. Define a
deterministic routine, using only canonical SMZ9 encodings:

1. Index recorded SHA-512 outputs by their preimages. From `r`, follow correctly
   framed internal-node preimages down the depth-23 tree. Reject ambiguous
   preimages or malformed paths. At a leaf, recover and parse the complete
   framed payload, including the authoritative salt and 64-byte leaf tape.
   Retain 140 data values and five mask values. Missing paths produce a fixed
   default row together with a separate missingness flag.
2. Call the resulting total, default-completed table `S_D(r)`. This is an
   extraction convention, **not recovery of every leaf originally committed
   by the adversary**. Agreement with accepted openings must be proved.
3. Compute the complete support
   `U = {i : for every j, R_j(x_i) = mask_j(i) + sum_c A_jc data_c(i)}`.
   If `|U| <= 387`, return `none`. Otherwise choose the first 388 positions in
   a fixed order, interpolate all 145 words, and verify agreement on all of
   `U`; return `none` on failure. This is the source decoder's algorithm.
4. Successful decoding gives a bounded-degree candidate whose projection is
   all of `R`, not merely its twenty opened values. The candidate uses `(S,A,R)`
   and no later PIOP batching challenge, PIOP opening points, or final query
   subset. The source-layout adapter spells out this interface in
   [`decodeMatrixSource`](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9McaSourceBinding.lean#L45).

The honest transcript order is

```text
root -> DECS matrix A -> response R -> PIOP batching gamma
     -> PIOP message -> six evaluation points -> PCS message -> twenty positions
```

The source prover and verifier are
[`piop_run`](../../../circuits/transaction/src/smallwood_engine.rs#L9980),
[`piop_recompute_transcript`](../../../circuits/transaction/src/smallwood_engine.rs#L10049),
and the [candidate verification path](../../../circuits/transaction/src/smallwood_engine.rs#L5340).
Verification reconstructs earlier transcript material starting from the proof's
`h_piop`; that reverse computation does not establish the malicious prover's
forward query order.

An arbitrary QROM adversary need not publish `r` or `R` before querying gamma.
It can query coherent superpositions of prefixes and reveal only final proof
bytes. Measuring the database at final verification and running steps 1–4
therefore produces a *post-challenge* object. Twenty verified opening paths
do not repair the timing: they contain only twenty rows, below the 388-row
interpolation requirement, and may include verifier-inserted records.

## Exact theorem interface to implement next

Define `MTExtractSmz9(D, prefix)` by step 1, with bounded byte input, deterministic
tie-breaking, explicit failure flags, and finite sparse database storage.
Implement its reversible extension on the compressed-oracle basis; no
measurement, nonlinear state-dependent map, or free postselection is allowed.
The required theorem must prove all of the following for this one operation:

- Coherent extraction and uncomputation are valid isometries, with an explicit
  gate/workspace bound. The adversary retains its residual quantum register.
- Substituting extracted source messages into the exact prefix query preserves
  the oracle interaction up to a derived commutation/indistinguishability
  bound, including adaptive oracle access by the extractor itself.
- Final accepted Merkle openings disagree with the corresponding extracted
  source only within a derived commitment-extraction bad event. A database
  measured after verification must not be silently substituted for the
  database at the relevant coherent prefix operation.
- The result reaches a state-restoration game for the actual protocol, not an
  oracle that returns an independent full logical challenge product in one
  query. The mapping accounts for every SHA-512 counter block, field-word
  conversion, admissibility retry, and distinct-subset sampling step.

The raw encoding to match is
[`RawSha512OracleKey.preimage`](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9WholeViewObservation.lean#L155),
checked against
[`concrete_smallwood_sha512_oracle_query_v1`](../../../circuits/transaction/src/smallwood_engine.rs#L4237).
Domain separation cannot be replaced by independently sampled logical outputs
without proving the coherent simulation and charging its query overhead.

After that theorem, prove the source decoder's **actual relaxed
round-by-round knowledge error**. The current
[`decoder_failure_probability_le`](../../../formal/crypto/HegemonCrypto/SmallWoodV8Smz9McaDecoder.lean#L295)
still contains `universalLineBudget`. A fixed-source, ideal-random-matrix
`p^-5` estimate is not automatically a one-record compressed-database
instability bound: other counter blocks and related challenges may already be
recorded. A concrete counter-block/state-restoration argument is required.

## Applicable primary results, with boundaries

**Don–Fehr–Majenz–Schaffner, online extraction.** Theorem 4.3 provides an
extractable random-oracle simulator; for hash preimages one exchange between
independent extraction/oracle calls costs at most
`8 sqrt(2 / 2^n)` in trace distance. Corollary 4.8, for `ell` classically
announced targets and `q` oracle queries, bounds disturbance by
`8 ell (q + ell) sqrt(2 / 2^n)` and extraction mismatch by
`8 ell (q + 1) sqrt(2 / 2^n) + (40 e^2 (q + ell + 1)^3 + 2) / 2^n`.
Its classical target interface is precisely why it cannot alone justify the
SMZ9 coherent prefix substitution. [Primary paper](https://eprint.iacr.org/2021/280.pdf).

**Faisal, interactive oracle arguments.** Appendix A constructs top-down online
Merkle extraction after a classical root announcement, with explicit
disturbance and opening-consistency analysis. This supports the feasibility
of the tree routine, but its announcement point cannot be invented inside an
arbitrary noninteractive quantum computation. Its tree representation and
leaf-hashing convention also require an exact SMZ9 translation before using
its constants. [Primary paper](https://eprint.iacr.org/2023/421.pdf).

**Don–Fehr–Majenz–Schaffner, efficient NIZKs from commit-and-open.** Theorem 5.2
gives an online knowledge bound for Merkle commit-and-open protocols of the
form `(22 ell log ell + 60) q^3 / 2^n + 20 q^2 p_triv`, under its special
soundness hypotheses. SMZ9's multi-stage oracle protocol has not been shown
to satisfy that interface. It is not a license to substitute the ideal DECS
estimate for `p_triv`. [Primary paper](https://arxiv.org/pdf/2202.13730).

**Chiesa–Di–Hu–Zheng, post-quantum noninteractive reductions.** Theorem 11.3
composes post-quantum state-restoration knowledge soundness with suitable
vector-commitment multi-extractability. Theorems 6.9–6.10 obtain quantum
state-restoration security from classical round-by-round security, including
the relaxed knowledge variant, with asymptotic loss
`O((t + k)^2 kappa_RRBR)`. Crucially, its commitment requirement supports
extraction of long messages in coherent queries, which earlier extraction
interfaces do not suffice to express. This is the relevant general framework.
Only the primary paper's indexed introduction/theorem summaries were available
for this assessment; its full concrete hypotheses/constants must be checked
before an SMZ9 instantiation is credited. [Official paper record](https://eprint.iacr.org/2025/2166),
[primary-paper mirror](https://files01.core.ac.uk/download/690750245.pdf).

## Resource ledger and claim boundary

For `N = 2^23`, the table alone is `N * 145 * 8 = 9,730,785,280` bytes
(9.0625 GiB); salts, tapes, database records and quantum workspace are extra.
A dense table is unnecessary for the tree index, but the decoder scans the
complete support. A direct implementation costs
`O(N * 5 * (140 + 388))` field operations to form support, plus
`O(145 * 388^2 + 145 * |U| * 388)` for interpolation and checking.
The polynomial coefficients occupy 450,080 bytes at eight bytes each.
These are algorithmic estimates, not measured Lean executable performance.

A fully expanded binary tree requires at most `2N - 1` preimage lookups when
each leaf payload is itself hashed. A naive reversible database scan adds a
factor proportional to database size; an efficient coherent implementation
and its uncomputation still need a gate bound. Polynomial in `N` is not the
same claim as practical laptop extraction, and an asymptotic protocol family
must account explicitly for how `N` grows with the security parameter.

The classical DFMS bounds indicate terms scaling like `q N / 2^256` and
`q^3 / 2^512` for full SHA-512 commitments. They are **not** the established
loss for the needed coherent SMZ9 reduction. The 2026 framework's `O` notation
cannot establish a concrete 128-bit margin.

Use a single lifetime adversarial query budget `Q`, include the mapped
verifier/extractor queries in the reduction's `q`, and account separately for
`V` extraction targets. Do not replace `V` by honest-proof-view count `T`.
`Q + 2NT` in existing eager accounting counts programming exposures, not by
itself every raw verifier/XOF query. No final numerical bound is available
until the concrete coherent extraction, decoder RRBR error, raw expansion
mapping, target composition, and packed-program-to-semantic extraction are
all proved. The [security contract](security-contract.md) remains unsatisfied.
