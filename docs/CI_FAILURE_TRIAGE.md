# Manual RP05 failure triage

In **Actions → CI failure triage → Run workflow**, select `main`, choose `run`, and enter the numeric ID of a failed **RP05 proof package** run. The collector checks GitHub's repository, event, branch, workflow, attempt, job and step metadata. It accepts completed failures from pushes, schedules and manual runs on the public upstream `main`. It reads one failed step and rejects logs larger than 64 KiB. The pilot recognizes source-manifest errors and the Lean kernel memory diagnostic in the cold proof step. An expired log, an earlier unknown diagnostic or a failure elsewhere produces a skip. An accepted run links back to its original failed step.

The report runs on a fresh runner at the trusted dispatch commit. Only a fixed diagnostic code crosses between jobs. It sends the failing command, a sanitized first error and a short explanation of the check to the OpenAI Responses API. The summary shows the evidence, labels any model interpretation as tentative, and gives one human verification step. A missing key or API error still produces an evidence summary. Each execution of the report job can make one request with up to 128 output tokens and response storage disabled. Rerunning the job can use credits again.

**One-time setup and smoke test**

1. Claim the ChatGPT API benefit for the intended organization and confirm an active balance in **API Platform → Billing → Credit grants**. Create a dedicated project API key in that organization with permission to create Responses. Free credits are used first. Purchased credits can fund later requests if the grant runs out. A grant-only setup uses an organization with no purchased balance and Auto Recharge off. [OpenAI's credit guide](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)
2. In **Pauli-Group/Hegemon → Settings → Environments**, create `ci-triage-main`. Under **Deployment branches and tags**, choose **Selected branches and tags**, add the exact **Branch** rule `main`, and leave the tag list empty. Then add **Environment secret** `HEGEMON_CI_TRIAGE_OPENAI_API_KEY` there. Storing the key at environment scope lets GitHub enforce the branch restriction even if another branch changes its workflow. [GitHub environment settings](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)
3. Once the workflow is on `main`, dispatch **CI failure triage** once on `main` with mode `smoke` and a blank run ID. The collector changes one staged Lean file in a temporary copy and checks that the real source guard rejects it. In the run summary, look for the smoke label, the sanitized hash mismatch, **Model interpretation (tentative)**, and one suggested verification. The model interpretation confirms a successful API response. The OpenAI project's Usage page records the request.

For offline regression checks, run `python3 -I -B -m unittest discover -s scripts -p 'test_ci_triage_*.py'`. The tests use Python's standard library and Ruby's bundled YAML parser. API responses and GitHub run metadata are mocked.
