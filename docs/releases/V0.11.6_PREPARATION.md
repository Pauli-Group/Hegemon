# Hegemon v0.11.6 pre-mainnet candidate

v0.11.6 adds opt-in payout-key rotation for solo miners. The full wallet derives a distinct spending key for each network block height. It exports the corresponding public addresses for the mining node, and recognizes the rewards again when restored from a full encrypted wallet backup.

This update also corrects the V6 diagnostic circuit's asset-slot counts for active and padded notes. The production PrivateSpend proof relation and its source digest are the same as in v0.11.5. ASIC timestamp rolling remains scheduled at pre-mainnet block 28,860. The network and wallet keep their existing genesis and storage formats.

## Solo miner setup

Use the candidate's node and wallet tools together. Keep the encrypted wallet backup and passphrase on the wallet host. The included `operator-guide.md` covers schedule export and renewal and wallet restore. Its source is `runbooks/miner_wallet_quickstart.md`.

Configure the miner with one public payout address or a payout schedule. The schedule can cover up to 4,096 consecutive network heights. Renew it before those heights pass. The miner pauses work when the schedule runs out. The public reward keys differ by height, while amounts and individual payout keys remain visible on chain.

If you switch the miner back to a fixed payout address, use the rotation-capable wallet to recover and spend rewards already issued to rotated keys.

All miners on the shared pre-mainnet network use the approved seed list:

```bash
export HEGEMON_SEEDS="hegemon.pauli.group:30333,devnet.hegemonprotocol.com:30333"
```

Enable NTP or chrony to keep timestamps within the future-skew limit.
