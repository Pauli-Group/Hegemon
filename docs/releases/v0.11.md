# v0.11 pre-mainnet release checklist

v0.11 starts a fresh HGN-only test network. Mainnet is planned as v1.00.
The PR prepares the source, release files and CI artifacts. It does not stop
v0.10.3, deploy a service, create a tag or publish a release.

## Before cutover

1. Review and merge the v0.11 source through the required GitHub checks. Product
   version is 0.11.0; release/display/tag is v0.11. Internal Cargo package versions
   remain unchanged because Cargo.lock is part of the qualified proof identity.
   Keep unchanged PR205 and later
   qualified protocol evidence under their original source/artifact identities.
2. Build final platform binaries from the release source. Verify their source
   and artifact manifests, proof authorization and required affected lifecycle
   checks. A version bump changes source/binary provenance; it does not authorize
   rewriting old G8 seals. Report actual platform coverage and any failed checks.
3. Freeze the fresh public network manifest and its release record. Retain the
   approved treasury recipient, 120-block maturity and HGN-only feature posture.
   Stablecoins and merge mining remain disabled; neither an arbitrary shutdown
   height nor a lifetime transaction quota is introduced.
4. Verify the treasury backup/restore record and the full public miner recipient
   chosen by the user for every mining host. Keep spending keys off the nodes
   and out of Git; public payout addresses are sufficient for mining.
5. Review the [operator guide](../../config/testnet/0.11/README.md) and packaged
   install procedure. Pending release metadata must not start a public join.
   Leave the old OVH service, wallets and database unchanged.

## After the operator announces the v0.10.3 shutdown

1. Preserve the old chain state, binaries, service configuration and wallet
   backups. Perform the separately authorized stop and v0.11 installation.
2. Use fresh state on `hegemon-ovh` (primary seed) and `hegemon-dev` (secondary).
   Verify the same manifest, genesis, chain/rules and artifact hashes. Confirm
   NTP/chrony and loopback RPC before enabling the selected mining roles.
3. Test canonical progress, two-host peer connectivity and user-controlled miner
   reward recipients. If retesting locally, run a fresh syncing node without
   mining and compare canonical block hashes.
4. Verify a clean-user install from the final release files and public guide.
   Then publish the approved onboarding announcement to Discord.

During pre-mainnet, observe real mining/sync/restart/reorg and wallet operations
for one to two weeks, including reward maturity and ordinary/HTLC transfers.
Use the observations to choose the mainnet date and separate mainnet identity.
Do not infer mainnet readiness or authority from a green pre-mainnet CI run.
