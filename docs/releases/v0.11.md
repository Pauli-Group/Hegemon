# v0.11 pre-mainnet release

v0.11 opens a fresh HGN-only pre-mainnet test network. Mainnet is planned as
v1.00 with a separate launch identity. Old v0.10.3 balances, databases and proofs
do not migrate; retain old state and wallet backups.

## Public network and joining

Use the [v0.11 operator guide](../../config/testnet/0.11/README.md) and the
platform package from the [release](https://github.com/Pauli-Group/Hegemon/releases/tag/v0.11).
Python 3 is required by the metadata-verifying launchers. The extracted package
contains normalized `bin/` executables, the standard-library Python launcher
`start.py`, optional `start.sh`/`start.cmd` wrappers, and the versioned network
metadata. Run `python3 start.py` on Linux/macOS or `py -3 start.py` on Windows.
Sync/relay is the default;
mining requires `HEGEMON_MINE=1` and the miner's own full V8 public address.
Keep NTP/chrony or OS automatic time synchronization enabled and RPC on loopback.
Funded local CLI submission requires the explicit `--wallet-rpc` launcher option;
it enables unsafe methods on loopback only. Public mining servers keep safe RPC.

## Binary and packaging provenance

The packages promote the existing qualified binaries unchanged: four each for
Linux x86_64, macOS ARM64, macOS x86_64 and Windows x86_64. Their binary build
provenance is source commit `46895bf8734ccedf1e7b31c44a43b9a7212597fc`,
source tree `3bfa87d491879734c0f1b69bea65fa374aad3c77`. The per-platform artifact
manifests under `provenance/` retain their exact checksums and original source
identity. `SHA256SUMS` covers each package's contents, and `bundle.json` records
the packaging source commit. Final
network metadata, documentation and launchers come from the separately recorded
packaging source commit; those updates do not imply a binary rebuild.

All four platform qualification receipts passed five real proof fixtures and
30 malformed-proof rejections per platform. The inner proofs measure
**171,281 bytes** each; the 688-byte fixture public statement is separate.
Unchanged PR205 and subsequent protocol/formal evidence retain their original
source and artifact identities. Packaging metadata does not rewrite old seals.

The later operational cutover established two-host mining, peer connectivity,
shared canonical blocks, restart continuity and fresh local synchronization.
A mature mining reward funded a **0.01 HGN** ordinary CLI payment to the existing
treasury. Its **0.00001 HGN** fee and **3.98999 HGN** change were reconciled;
the transaction's canonical inclusion was checked on OVH, dev and the local
syncing node, and the treasury wallet received the payment. The fee credit in
block 131 is itself a coinbase reward and matures at height 251.

The cutover reuses the unchanged qualified HTLC and exact 120-block maturity
boundary evidence. It does not claim newly repeated HTLC/boundary checks or
funded desktop GUI sends. Desktop app coverage remains fresh-wallet sync only;
use the native `private-spend` CLI for funded operations.

## Release and operator checks

Before announcing public onboarding, verify the published archive and binary
checksums, the package's metadata/source provenance, and a clean-user join using
the public guide. Compare the node's height-zero block hash and chain ID with
the table above, confirm peers and advancing canonical height, and confirm the
same canonical block hashes as the seeds. Preserve old state paths and keep
spending keys off mining servers. Publishing the package and announcement are
separate actions from these technical receipts.

During pre-mainnet, observe mining, sync, restart, reorg and wallet behavior for
one to two weeks, including ordinary and HTLC operations and reward maturity.
Use those observations to choose the separate mainnet date and identity.
Stablecoin and merge-mining activation require a later coordinated consensus
upgrade and their own readiness review.

## Verify the packaged proof backend offline

The packaged node can verify a public proof without starting RPC, opening chain
state or connecting to peers. This optional diagnostic requires matching proof
fixture files obtained separately from the join package:

```sh
./bin/hegemon-node verify-private-spend \
  --statement '<ordinary.statement>' \
  --proof '<ordinary.proof>'
```

The five cases cover ordinary spending, policy creation, an absolute-height
lock, policy hash release and explicit HTLC secret release. Successful
verification emits JSON. This command checks the cryptographic backend; it does
not submit a transaction or establish its canonical-chain inclusion. The
platform receipts also reject six malformed inputs per case and treat crashes
as failures.
