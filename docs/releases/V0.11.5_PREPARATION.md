# v0.11.5 source preparation

This PR adds bounded Bitcoin80 time rolling on the existing pre-mainnet chain,
scheduled at H28,860. It stacks on
`codex/sync-recovery-current-network-20261110` at
`ad77c8d564944972b6ae5e7cab26fcf500972aff`, preserving v0.11.4 and subsequent
sync fixes. The product label is 0.11.5; internal Cargo package versions and
the exact proof-bound Cargo.lock remain unchanged.

The [consensus specification](../consensus/NTIME_ROLLING.md) defines header
commitment, range semantics, RPC fields and the Friday November 20 Calgary
morning estimate. H28,860 governs activation; no wall-clock trigger is used.
The original H18,660 ASERT anchor and treasury cadence remain active.

This document records source preparation, not accepted release artifacts.
`config/testnet/0.11/release.json`, v0.11.4 artifact pins, historic packagers and
qualification receipts continue to describe the published predecessor. They
must not be relabeled as v0.11.5 evidence. Publication requires an additive
v0.11.5 packaging profile bound to the new source and ordinary release binaries,
the required platform/proof and lifecycle qualification, independent review,
and the applicable release authorization. Operators and miners should receive
the announcement once that release is ready, with enough time to update before
H28,860. This PR does not publish, deploy or send that announcement.

## Inherited dependency audit blocker

The first PR CI run's dependency audit rejected the unchanged lockfile with
four unwaived advisories: RUSTSEC-2026-0524 and RUSTSEC-2026-0523
(`quinn-proto 0.11.18`), RUSTSEC-2026-0538 (`quinn-udp 0.5.15`) and
RUSTSEC-2026-0486 (`rustix 1.1.4`). See
[the CI run](https://github.com/Pauli-Group/Hegemon/actions/runs/43540344341).
This records the audit result, not an assessment of reachable attack paths.
The PR neither adds waivers nor changes those dependencies. Cargo.lock is an
exact transaction-proof relation input, so dependency remediation requires the
corresponding proof/release qualification; it cannot be hidden in a version bump.
Release readiness remains blocked until that gate is resolved.

## Broader CI regressions

The first Monorepo run also reported two rapid higher-peer-hint regression
failures in `sync_queue_qualification_tests` and `mining_recovery_qualification_tests`,
and an HTTP worker-capacity failure in `public_rpc_http_tests`. Those
implementation/test files are unchanged by this PR. Each sync failure was
reproduced by executing its exact test on both this PR and clean baseline
`ad77c8d564944972b6ae5e7cab26fcf500972aff`: retained heights H4 versus expected
H5, and H1 versus H2 respectively. Each invocation executed exactly one test.
The HTTP test passed in isolation on both sources; its full-suite CI failure
remains unexplained and is not declared resolved. Draft status preserves these
visible readiness blockers.
