# v0.11.5 unpublished release preparation

This PR adds bounded Bitcoin80 time rolling on the existing pre-mainnet chain,
scheduled at H28,860. It stacks on
`codex/sync-recovery-current-network-20261110` at
`ad77c8d564944972b6ae5e7cab26fcf500972aff`, preserving v0.11.4 and subsequent
sync fixes. The product label is 0.11.5; internal Cargo package versions and
the exact proof-bound Cargo.lock remain unchanged.

The [consensus specification](../consensus/NTIME_ROLLING.md) defines header
commitment, range semantics, RPC fields and the Friday November 20 Calgary
morning estimate. H28,860 governs activation; no wall-clock trigger is used.
The original H18,660 ASERT anchor and treasury cadence remain active.

Release preparation uses a distinct v0.11.5 source/artifact profile. The historical
`config/testnet/0.11/release.json`, v0.11.4 pins, packagers and receipts retain
their original attribution. `config/v0115-release-artifacts.json` is the current
machine-readable packaging status: `pending` cannot package; `accepted` pins
one exact successful non-PR preparation run, frozen source and all four platform
manifests and final proof/H0/lifecycle receipts. Acceptance prepares verified
archives and checksums. It grants no publication, deployment, activation,
mainnet or physical-hardware authority.

The **Prepare pre-mainnet release** workflow runs its nine required jobs on an
explicit push to `codex/v0.11.5-ntime-rolling` or a manual dispatch. It only
uploads retained Actions artifacts. It does not create a tag or GitHub Release.
The Monorepo push lane additionally executes its full Lean and vector checks;
PR checks alone intentionally omit those jobs and cannot establish complete
release qualification. The final accepted packaging profile may be the only
source change after the build commit; executable, test, workflow and proof
inputs remain frozen. Publication and the operator announcement require a
separate instruction after all required CI and final-artifact checks pass.

## Final qualification and package verification

`scripts/check_ntime_rolling_candidate.py` binds the exact current source,
independent internal review and unchanged 41-input transaction-proof identity.
Its final phase executes current ordinary release binaries against actual
self-contained proof artifacts, negative controls and a disposable height-zero
node identity check. The affected lifecycle runner separately executes the
source-owned native time/ASERT/treasury/version/sync and Stratum regression
suites, with exact positive test counts. A rehearsal executable is identified
separately from the ordinary release binaries. Historical funded proof evidence
continues to describe its original source and run; it is not a fresh funded
HTLC/recovery or physical ASIC run for this release.

The v0.11.5 proof executor keeps the historical proof predicates and fixtures
byte-identical while binding a separately reviewed process-control harness.
On Windows it creates each suspended verifier inside its owned Job Object,
with kill-on-close and an exact inherited stdio handle list, checks membership,
then resumes the primary thread. The receipt must identify that harness and
record successful containment and cleanup for every proof and negative control.
Native Windows rapid-exit, descendant and timeout regressions run in a fast
independent CI job and before the Windows preparation build. A failed
containment operation remains a qualification failure.

The first preparation attempt at `1bcfa01` passed all 22 Monorepo push jobs and
the complete Linux platform job, but Windows proof qualification failed with
`cannot assign owned job`. That historical runner started the child before
assigning its job and did not retain the Win32 error code, so the precise cause
was not established. That attempt cannot qualify this release. The additive
containment fix requires a fresh source freeze and complete preparation run.

`scripts/package_v0115_release.py` derives the accepted packaging profile from
the successful preparation run JSON, four native platform manifests and four
manifest-bound final receipts. It rejects unfinished jobs, another source
commit, a different lock/proof identity, absent receipts, relabeled v0.11.4
assets, or any postbuild change besides the single packaging profile. Run its
`--help` for the explicit `--assets`, `--qualification-receipts`, `--ci-run`,
`--build-source` and `--derive-profile` inputs. After committing the accepted
profile, rerun without `--derive-profile` to produce deterministic archives and
checksums. Retain both the raw preparation artifacts and packaged output; do
not publish or tag as part of preparation.

Internal delta review renews only scopes actually examined from the last
recorded review through the frozen source. All 122 external review statuses
remain pending. Governance execution receipts are renewed only after the
pinned 14-test recipe actually passes, followed by the complete Lean, axiom,
policy, crypto and executable CI checks. No receipt update stands in for one

Cargo.lock remains exact because it is a transaction-proof relation input.

## Native CI fixture fixes

The two original rapid-higher-hint failures reproduced on the unchanged base.
The tests assumed an unverified hint could replace a fresh exact sync target,
contrary to the existing anti-pinning design. Revised fixtures require the
fresh request to remain anchored, admit a higher target only after expiry or
owner release, isolate old completion state and perform the real final import.
No production sync scheduling behavior changes.

The HTTP capacity test raced reservation during body collection against actual
blocking-worker ownership. A bounded per-node test observer now waits for both
workers before disconnecting clients. All capacity, 429, release and no-write
assertions remain; the separate unstarted-body cancellation test stays intact.
The full minimal and default native suites each passed 1,017 tests locally
with 12 existing ignored tests after these changes.
