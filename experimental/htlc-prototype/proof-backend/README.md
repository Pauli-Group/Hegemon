# Native private SHA-256 hashlock component proof

This nested standalone crate exercises the unchanged Hegemon SmallWood core against the complete relation `exists secret:[u8;32]. SHA256(secret) == public_digest`. Its public context is opaque transcript-bound bytes. It does not authenticate that context, enforce HTLC claim/refund authority, commit/open a shielded note or nullifier, check timeout, or produce a production transaction proof. The host HTLC reference relation remains in the parent prototype.

The first K64 proof was generated and verified on 2026-10-02: 311,938 bytes, 4.519 seconds proving and 0.140 seconds verification. A separate process accepted the unchanged retained bytes from only the public statement and proof. An actual proof generated from a coherent wrong-secret SHA trace while bypassing host preflight was rejected. This measured component proof exceeds the unchanged production cap. Exact receipts, hashes, falsification results and geometry projections are in [`MEASUREMENTS.md`](MEASUREMENTS.md).

`build.rs` generates a facade from the original transaction crate root, changing module resolution to absolute paths pointing at original source. The original RNG module's nested `mod mapping;` and `mod tapes;` declarations receive absolute child paths in a generated copy because source inclusion otherwise changes Rust's relative lookup. Their function bodies remain unchanged. The engine source is included unchanged, with a local read-only wrapper around its private configuration/size calculators for projections. There is no backend fork, protocol edit or production module-visibility edit. The local crate can call the existing crate-local generic constraint/prover/verifier APIs. The conservative source inventory covers original transaction/local-dependency Rust files, manifests, workspace/toolchain pins and both isolated crates; the nested Cargo.lock pins registry checksums. The closure SHA-256 and actual rustc version also enter the experiment's public transcript binding. The artifact therefore expects the same source closure/toolchain when verified.

`ClaimAdapter::from_statement` reconstructs the fixed verifier-owned SHA topology from only version, public digest and public context. `src/lowering.rs` in the parent crate packs Booleanity directly over canonical rows, groups each gate polynomial into operand rows and copies every occurrence back to its canonical wire with a sparse linear equation. Two constants, canonical padding and 256 digest output bits are pinned. The 256 secret input bits have zero public pin equations and no auxiliary openings. Partial gate batches repeat a valid final gate, rather than use invalid zero-filled NOT gates.

Exact K64 lowering: 4,159 rows, 266,176 packed values, 1,730 nonlinear polynomials, 210,968 linear constraints (210,688 copies, two constants, 256 public digest pins, 22 zero-padding pins), maximum degree three. Canonical Boolean equations cover all 55,488 padded canonical bits. This geometry differs from production RP05 and is not admitted by its production route.

The first proof profile is the historical strict SMZ1 native engine: Goldilocks field, K64 packing, degree three, rho five, five PIOP openings, beta two, DECS domain 2^20, 23 DECS queries, eta five, zero grinding, disjoint evaluation coset, 64-byte hiding tapes and SHA-512 transcript. No production cap or geometry is changed. No RP05, composed PQ128 or general ZK theorem is inherited for this new relation/geometry. Source inclusion and a valid roundtrip do not discharge soundness, Fiat-Shamir, RNG, privacy or compiler-refinement hypotheses.

The runner requires a nonexistent output directory and preserves retained artifacts. It generates an OS-random 32-byte secret, never writes/logs that secret or its witness, retains `statement.json`, `claim.smz1`, source inventory and the measured result, then verifies the actual proof. It tests changed digest/context/version/domain, changed proof byte, appended byte and wrong-secret rejection. `--negative-engine` additionally forces a coherent SHA trace for a wrong secret through the actual prover while bypassing the host preflight; a returned proof must fail the real verifier. That additional proving run is explicit because it consumes comparable resources to the honest run. `--verify-artifact` reopens only the retained public statement and proof in a fresh process; it has no secret/assignment input, denies unknown statement fields and bounds artifact input size.

The report compares actual experimental proof bytes against the unchanged 164,113-byte production RP05 inner cap and reports fit/failure honestly. Passing that size comparison would still confer no production compatibility or authority. Full HTLC proof semantics, security qualification and unchanged-byte node lifecycle remain separate future obligations.
